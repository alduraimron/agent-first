# sharpen - Requirement Discovery

## Intent and trigger

Improve a vague task into measurable outcomes and boundaries. Use when the user requests a sharper problem, specification, or acceptance criteria.

## Procedure

1. Find the motivating observation and desired change.
2. Isolate scope, constraints and non-goals.
3. Convert vague quality words to observable checks.
4. Surface unresolved high-risk forks.

## Output contract

Short problem statement, non-goals and observable acceptance criteria.

## Boundaries and failure modes

Read `skill://af-interaction` for shared boundaries if not already loaded. Follow shared RULES.md, accepted project decisions, and native permissions. Avoid excessive decomposition or invented product requirements. Sharpening a specification does not authorize implementation or running the proposed acceptance checks. Label observations, inferences, unknowns, and unexecuted checks separately. Keep answers proportional; advisors are optional for material specialist questions.

## Example invocation

- User: Sharpen these requirements into acceptance criteria.
- Success: Produce measurable criteria and identify decision-changing gaps without inventing requirements.

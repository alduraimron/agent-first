# Full implementation plan

## Fixed architecture

Keep the existing explicitly activated `agent-first` OMP profile. OMP performs routing, native task delegation, approvals, session history, and browser integration. Files provide procedures and authoritative project decisions; no extension, plugin, server, memory database, or second orchestrator is added.

1. Expand `af-engineering` into an adaptive router over eight disclosed procedures. Preserve the three Phase 1 route names and behavior for ordinary fixes/features/architecture changes.
2. Add six domain advisors and focused engineering skills. Main owns implementation and execution; advisors inspect and propose constraints. Reuse the bundled reviewer. Keep concurrency two, one delegation level, and existing permission denies.
3. Add `af-context` and minimal `.agent-first/` project templates for facts, requirements/acceptance/plans, decisions, progress/handoff, evidence, issues, and corrections. Recover these files before meaningful resumed work; native sessions retain execution detail.
4. Expand verification with explicit PASS/FAIL/NOT-RUN/NOT-APPLICABLE outcomes and domain checks selected from existing project tools. Use Tern for actual UI interaction, with backend identity and limitations recorded.
5. Add opt-in OVNFS lifecycle guidance using installed native commands. Keep automatic application disabled and denied; integration remains a separately approved operator action after diff/dry-run inspection.
6. Preserve prior evaluation cases/results. Add behavioral cases for all routes/specialists, recovery, review-only work, failure/approval handling, and a UI task. Run actual API/SQLite/security/performance and Tern checks, plus disposable OVNFS checks. Record failures without broadening permissions.
7. Publish usage, architecture, evaluation results, limitations, and an evidence-based improvement backlog. Do not automatically commit or push this change.

## Decision boundaries

Local reversible implementation choices within the requested outcome proceed without ceremonial approval. Installs/updates, permission expansion, production changes, external side effects, unrequested breaking contracts, and source integration from isolation require explicit scope/approval. Existing team/default-profile configuration stays untouched.

## Verification contract

Use observed native configuration/context and task journals, actual process exit/results, independent consumer behavior, live browser state, measured timings, and disposable filesystem state. A route label or advisory opinion is not proof. Retain raw private evidence outside tracked source; portable documentation distinguishes observed facts, assumptions, incomplete checks, and proposed improvements.
